预算充足，无淘汰 超过 64 KB 时，从作用域最宽的文件开始淘汰——淘汰会写日志，面板也会亮「有淘汰」警告，不再静默丢弃

四种状态标记

规则位置的当前状态
  • 已启用 —— 规则存在，会被加载
  • 不存在 —— 这个位置没有规则
  • 已注入 —— 本次会话已经送进上下文
  • 已淘汰 —— 预算超限，被更窄的规则挤掉了

[官方] 与 [插件]

规则由谁负责处理
  • 官方 —— DSH 自带机制（AGENTS.md / CLAUDE.md），本插件只读取状态用于展示，绝不重复注入
  • 插件 —— 本插件（rules/ 目录与白名单目录）
  • 两者并行，不冲突。
PREHEAT

预热：让规则立刻生效

第一次动某个文件夹时规则还没生效——而第一次往往最需要规则。

问题

子目录规则是「按需」的：第一次操作时还没加载，可第一次恰恰最需要规则兜底。

解决

在面板「L5 子目录规则」列表里点「开启预热」：对正在运行的会话，下一步即注入；之后每个新会话启动时自动加载。

注意

预热的目录计入预算，只为高频动工的目录开启。预热清单按工作区存在 ~/.dsh/rule-lens.json，重启自动读取。

WRITE-BACK GUARD

写回防护：强制层的第一道闸

对工作区内已存在的 .md 文件用 write 整体覆盖 → 直接拒绝。整体覆盖容易冲掉既有内容；定向修改请走 edit。

拦什么

  • write 整体覆盖工作区内已存在的 .md —— 直接拒绝

不拦什么

  • write 新建文件
  • write 非 .md 文件
  • edit / str_replace_editor 定向修改
  • 工作区外的文件
逃生口：拒绝提示的最后一句是「若确实需要全文重写，请先向用户说明理由并取得同意」——需要时 AI 会来问你。关闭：面板「设置」区点一下开关，或改 ~/.dsh/settings.yaml 的 rule-lens.writeGuard。
FORBID

FORBID 硬规则：规则文件里的红线

普通规则是「建议层」——模型大概率遵守；FORBID 是「强制层」——写进规则文件的一行声明，直接变成工具调用前的硬拦截。与写回防护同层，每次拦截都记入遵守率。

语法：一行一条

写在任何被加载的规则文件里（含官方 AGENTS.md）
FORBID: <工具名 glob> <路径 glob> # 示例 FORBID: write *.env # 禁止 write 任何 .env FORBID: * **/secrets/** # 任何工具都不许碰 secrets/ FORBID: bash *rm -rf* # 拦 bash 里的危险命令 FORBID: bash * # 路径写 * = 该工具一律禁止

匹配规则

glob 语义，刻意保持简单
  • 工具名 glob 匹配工具名本身：write、bash、w*…
  • 路径 glob 同时试四种形态：原始参数、绝对路径、工作区相对路径、~ 折叠路径
  • * 不跨 /，** 跨 /，? 匹配单个字符
  • bash 的命令串不是路径：此时 * 可以跨 /（所以 *rm -rf* 能命中）
  • 路径 glob 写 *：该工具调用一律拦截
拦截时模型看到：「[规则透镜·硬规则] 命中规则「FORBID: …」（来源：某文件），已拦截某工具。若确实需要执行此操作，请先向用户说明理由并取得同意。」——来源文件会点名，方便你回头改规则。
LINT

规则体检：四类毛病当场报

面板的「规则 Lint」区对每一个已发现的规则文件做四项检查。有警告的文件逐条列出，全绿则显示 ✅。

① 超长

超过 100 行 报警。规则文件应保持简短；长篇说明请挪到文档，别让规则挤占预算。

② 没有禁令词

全文没有 不要 / 禁止 / 不得 / 严禁 / 绝不 / never / must not / do not 这类词，说明规则可能只是「建议」，模型容易当耳旁风。

③ 写成了教程

含 教程 / 什么是 / 入门 / introduction / tutorial / what is / getting started 等词报警。规则文件只留约束本身，不讲课。

④ 跨文件重复

两个文件内容按哈希判定完全重复时互相点名。重复规则白占预算，删一份。

LOGS & COMPLIANCE

注入日志与遵守率

每一次注入、每一次淘汰、每一次拦截都落在本地 JSONL 文件里。面板「日志导出」区一键下载。

log.jsonl · 注入日志

~/.dsh/rule-lens/log.jsonl · 每行一条
{"ts": # ISO 时间 "sessionId": # 会话 "layer": "L1|L2|L4|L5|WL-*", "path": # 展示路径 "bytes": 464, "mode": "startup|preheat|ondemand", "evicted": false }

compliance.jsonl · 遵守率

~/.dsh/rule-lens/compliance.jsonl · 拦截即兜底成功
  • 拦截事件（实时写入）：kind 是 write-guard 还是 forbid、工具、路径、命中的规则
  • 会话小结（会话结束写入）：注入/淘汰文件数、字节数、两类拦截各自次数
  • 面板「遵守率」区显示本会话集与历史聚合，并列出最近拦截明细
导出：面板底部「日志导出」区有两个按钮——「下载 log.jsonl」「下载 compliance.jsonl」，也可以直接点开卡片里显示的文件路径自行取用。
COMPATIBILITY

兼容其他工具（可选）

把 Cursor、Claude 等工具的规则目录也纳入「规则透镜」的视野。

在面板「设置」区的白名单输入框填目录名（以 . 开头，逗号分隔）

.cursor .claude

支持文件：.md 和 .mdc（Cursor 用 .mdc）。只允许单段目录名，带 / 会被拒绝。

生效范围

只在 ~/<名字>/rules/ 和 <库根>/<名字>/rules/ 两个位置查找，不进子文件夹。

例如白名单填 .cursor，插件会读取 ~/.cursor/rules/*.mdc。配置落在 ~/.dsh/settings.yaml 的 rule-lens.whitelistDirs。

FAQ

常见问题

踩坑前先看一眼，多数疑问这里都有答案。

规则写了但不生效？

按顺序排查：

  1. 位置对不对 —— 对照「规则放哪儿」表格
  2. 是不是 .md / .mdc
  3. 目录里至少有一个匹配文件吗 —— 空目录不认
  4. 是子目录规则吗 —— 那要等你先动一次，或开预热
  5. 看预算条 —— 是不是被挤掉了（面板会亮「已淘汰」）
  6. 面板显示「已注入」了吗 —— 只看「已启用」可能还没触发
  7. 看 log.jsonl —— 每次注入/淘汰都有一行，铁证
为什么第一次操作不生效？

机制设计，不是 bug。 规则加载是工具驱动的：只有在你成功 read / write / edit / str_replace_editor 之后才检查。想避免就开「预热」。

AGENTS.md 和 rules/ 有什么区别？

AGENTS.md 由官方处理、单文件、简单直接；rules/ 由本插件处理、目录可放多个、可按主题拆分。两个都用没问题。本插件只读官方文件的状态用于展示，不会重复注入。

规则会重复加载吗？

不会。 同一目录在一次会话里只注入一次；工作区的 .agents 与白名单目录属启动层，不会被当成子目录规则再注入一遍。

规则管不住模型怎么办？

普通规则是「建议层」，模型大概率遵守但不保证。两条升级路径：

  1. 红线类规则写成 FORBID: <工具glob> <路径glob>，直接进强制层硬拦截
  2. 先跑一遍面板「规则体检」——规则太长、太像教程、没有禁令词，都会显著降低遵守率
重启 DSH 后要重新配置吗？

不用。 全局开关（写回防护 / 预算 / 白名单）存在 ~/.dsh/settings.yaml 的 rule-lens 节；各工作区的预热清单存在 ~/.dsh/rule-lens.json。两处重启后都会自动读取。

LIMITS

已知限制

两层分明：建议层（规则注入）只能影响模型，强制层（写回防护 / FORBID）直接拦截。这三件事先要有预期。

建议层 ≠ 强制执行

注入的规则进了上下文，模型大概率遵守但不保证。要拦得住，用强制层：写回防护（自带）或 FORBID（自定义）。

没有文件监听

改了规则文件，要等下一次结构化文件操作才生效；同目录每会话只注入一次。

shell cd 不触发

只有 read / write / edit / str_replace_editor 这类结构化操作才算「触达」，在终端里 cd 过去不算。

四层模型：现在第四层也有了

一条规则的完整旅程：

规则被发现（面板「已启用」） 进入上下文（面板「已注入」，log.jsonl 有记录） 模型遵守 · 建议层，只能影响 违反被拦住 · 强制层（写回防护 / FORBID），拦截记入 compliance.jsonl

所以安全底线要么交给写回防护，要么写成 FORBID——别再只指望规则文件里的苦口婆心。

PRIORITY

规则优先级

从宽到窄共 6 层，后者覆盖前者；预算超限时反过来——最宽的先淘汰。

L1 ~/.agents/AGENTS.md全局单文件 · 插件
L2 ~/.agents/rules/*.md全局目录 · 插件
WL ~/<白名单>/rules/*  ·  <库根>/<白名单>/rules/*白名单 · 插件
L4 <库根>/.agents/rules/*.md库级目录 · 插件
L5 <子目录>/rules/*.md子目录 · 插件 · 按需
官方 AGENTS.md / CLAUDE.md 各层官方机制 · 插件只展示
范围越窄，优先级越高。 注入顺序 L1 → L2 → 白名单 → L4 → L5；预算淘汰顺序相反（L1 先走），最窄的一层永远保留。L5 中途超预算不回头淘汰旧内容，只亮警告。
